# 拾仓 · StockAssistant

本地运行的 A 股与场内 ETF 交易账本。React / TypeScript / Tailwind 界面、Radix 弹窗、TradingView Lightweight Charts 图表、FastAPI 服务、SQLite 数据库。

目录与入口见 [项目目录](docs/PROJECT_STRUCTURE.md)，辅助工具见 [脚本索引](scripts/README.md)。
日常改动更新源码和前端构建，不自动运行测试或重新打包便携版。

## 源码与本机数据

仓库只包含应用源码、构建脚本、文档及测试源码，不包含个人账本、成交导出、备份、账号授权、日志或逆向分析产物。
`data/`、`release/`、`build/`、`dist/` 和本机配置均不提交。首次运行会创建自己的空账本。
同花顺官方 `xiadanctl.exe` 需自行安装，仓库不附带第三方可执行文件或技能包；
可安装到下文默认技能目录，或设置 `STOCK_ASSISTANT_XIADANCTL`。基础记账功能不依赖该工具。

## 启动

需要 Python 3.12+、Node.js 20.19+ 和 npm。

双击 `start.cmd`，或在 PowerShell 中运行：

```powershell
.\start.ps1
```

首次启动会安装项目依赖，之后构建并启动服务。在浏览器打开 **http://127.0.0.1:8000**。保持终端开启，按 Ctrl+C 停止服务。服务默认只监听本机。

## 使用

1. 添加六位证券代码、名称和类型（股票或 ETF）。
2. 录入买入：交易时间、成交价格、数量和费用合计。
3. 录入卖出：默认先进先出，或指定一个买入批次；交易时间按本地时间填写。
4. 查看持仓、买入批次成本线、已实现盈亏和交易明细；点击未卖完的批次会突出成本线并打开卖出弹窗，自动选中该批次并填入剩余数量。
5. 在设置中导出 CSV 或备份整个 SQLite 数据库。

### 快捷录入

- 买入弹窗显示买 1～买 5，卖出显示卖 1～卖 5；点击档位填入盘口快照的价格。无有效报价时按钮禁用，可刷新或手动录入。
- 数量提供 100、500、1000 和 ±100 快捷按钮；新买入数量按 100 的倍数填写，编辑已有记录及卖出允许零股。
- 全仓、1/2 仓、1/3 仓、1/4 仓：买入使用同花顺当前账户返回的可买数量，不再设置手工可用资金。
- 卖出仓位按所填交易时间之前的账本持仓计算；编辑时排除正在编辑的交易。指定买入批次时仅计算该批次，分仓数量向下取整到 100，全仓包含零股。此处不校验券商 T+1 可卖数量。
- 所有快捷按钮只帮助填写交易记录，不会发送买卖委托。

### 买入盈利目标

买入弹窗可填写「本次买入期望盈利」，选择盈利率（%）或盈利金额（元），留空不设目标。每笔买入独立保存目标，编辑该买入记录可修改或清空；原有交易默认没有目标。数据库备份与 CSV 导出包含目标字段。

买入批次默认按买入日期、同日记录 ID 倒序显示。行情快照下预计盈利达到目标的未卖完批次以金色高亮、标记「已达标」并置顶；达标组内同样按时间倒序。列表显示顺序不影响先进先出计算。

预计盈利 = 最新价格 × 剩余数量 − 剩余买入成本（含已录入买入费用）− 按系统设置估算的本笔卖出佣金。盈利率目标以剩余买入成本为基数；金额目标按剩余数量 / 原始数量分摊。其他卖出费用未包含，请按实际费用在卖出时核对。

目标跟随行情刷新重新判断；可在系统设置开启自动刷新当前标的行情。无行情、行情过期或计算请求失败时，不高亮确认达标。已卖完批次不再判断目标。

空账本提供「查看示例」。示例交易和行情都是虚构数据，只存在于内存，不写入数据库；示例模式下不允许录入、编辑或删除。

### 同花顺券商查询

侧栏「券商账户」通过官方 `xiadan-ai-selector` 的 `xiadanctl.exe` 查询当前登录账户。
支持连接状态、持仓、资产、当日成交、当日委托、可撤委托，以及按日期查询历史成交、资金流水和交割单。
账户类型取自每次查询结果；切换同花顺账户后点击刷新。

工具默认查找 `~/.codex/skills/xiadan-ai-selector/scripts/xiadanctl.exe`，其次查找项目内
`xiadan-ai-selector/scripts/xiadanctl.exe`。其他安装位置可在启动前设置环境变量
`STOCK_ASSISTANT_XIADANCTL` 为完整工具路径。后端只允许上述查询命令。

同花顺下单客户端必须运行并登录，且启用本地 skill 服务。本机 `2026.10.09.1` 版本经验证，
在 `xiadan.ini` 现有 `[AI_TRADE]` 段加入 `mcp_test=1` 后重启，开始监听 `127.0.0.1:18600`。
该配置属于本机版本的验证结果，不保证其他版本相同。首次业务查询如弹出本机授权，在同花顺中确认。

券商查询不写入手工账本、费率设置，不缓存或持久保存账户快照。
查询结果只返回展示所需字段，过滤资金账号、股东账号及授权值；历史输入临时文件在查询完成后删除。
页面以券商返回的成本和盈亏为准；与手工账本计算口径可能不同。
历史成交费用在同时有成交金额和资金变动时推算，缺失字段显示 `—`，不会填成零。
信用账户试用版成交接口可能返回空结果，页面会提示结合委托结果确认。

接口更新后需要重启 StockAssistant 的后端（在运行窗口 Ctrl+C 停止，再运行 `start.cmd`）。

## 成本规则

- 每笔买入单位成本 =（成交价 × 数量 + 买入总费用）÷ 数量。
- 卖出按先进先出或指定批次分摊买入成本，不将指定批次不足的数量转移到其他批次。
- 剩余持仓成本 = 所有未卖完批次的剩余数量 × 各自单位成本。
- 已实现盈亏 = 卖出金额 − 卖出费用 − 对应买入成本。
- 浮动盈亏 = 最新行情价 × 剩余数量 − 剩余持仓成本，不预扣未来卖出费用。
- 在「设置与数据管理 → 手续费费率」中分别填写股票、ETF 交易佣金（万分之）与单笔最低手续费（元）。默认均为 0，请按自己的券商账户设置。
- 新交易自动估算佣金：`max(成交价 × 数量 × 佣金率 ÷ 10000, 单笔最低手续费)`，四舍五入到分，买卖均适用。仅包含佣金，其他费用需在总费用中手动补入。
- 手动修改总费用后，调整价格或数量不会覆盖手动费用；可点击「按费率重新计算」恢复自动模式。编辑已有交易默认保留原费用。修改费率不会重算历史记录。费率保存在 SQLite 数据库中，完整备份包含费率设置。
- 卖出弹窗的「本次卖出盈亏」= 卖出金额 − 对应买入成本（含买入费用）− 卖出费用；指定批次时按该批次计算，默认先进先出。预览只读取账本，不写入交易，计算结果与保存后的已实现盈亏采用同一算法。
- 服务端使用 Decimal 进行计算，数据库保留原始价格与费用的十进制字符串。展示金额会四舍五入，内部批次分摊保留高精度。
- 从交割单恢复的记录另外保留券商实际成交金额，成本与盈亏优先采用该金额，避免导出均价的四舍五入误差。只改备注或费用会保留原成交金额；修改价格或数量后改按新价格 × 数量计算。
- 所有增删改在事务内重新计算完整交易历史；持仓不足或指定批次无效会拒绝保存并回滚。
- 同一交易时间按记录 ID 排序。买卖顺序很重要时，请填写不同的交易时间。

当前版本适用于人民币 A 股及场内 ETF、单账户记账；不自动处理分红、送股、拆分、转入持仓、融资融券、T+1 可卖校验与多账户。应从首次买入开始录入；如已有持仓，可录入一笔带实际买入成本的期初买入。

## 当日成交合并

当日成交表格的卖出委托行提供“做 T”快速开关，作用于同一委托的全部分笔成交；同步前保存整单标记，同步及后续分笔成交继承，同步后切换更新已有账本记录。买入行不提供开关，部分成交状态不一致时显示“部分”。已有买回关联的委托须先解除关联才能关闭；开关仅管理本地做 T 标记，不提交交易或自动关联买回。

买入行同步后可直接点击“关联做 T 买回”，在弹窗中选择同标的待买回卖出委托及关联数量，按整单分摊并恢复原批次，支持部分关联、查看已有关系、恢复旧关联和解除。无需再次查询券商即可关联刚同步的买入；入口用原成交快照校验已同步交易身份，实际写入继续使用整单关联事务和数量、时间及历史成本保护。关联后刷新账本与卖出行的关联状态，不提交真实委托。

当日成交按可靠的委托号、证券、方向、交易日期合并为表格行，成交均价为总成交金额除以总成交数量，按最近成交时间倒序排列，展开保留每笔明细。缺少可靠委托号或成交编号的记录独立展示，不按时间猜测合并。点击“同步本委托”在同一事务中逐笔记账、保留原成交指纹与真实时间，重复查询和同步不会重复写入；部分已同步时只处理剩余成交。手动指定批次适用于整组待同步数量，多批次分摊按成交时间依次消耗用户指定的分摊数量。

缺失费用时按该委托已知成交总金额估算一次佣金，再按成交金额累计分摊到分；新增成交同步时重新分摊本程序记录且未被修改的估算费用，最低佣金不会按每笔成交重复收取。`broker_deal_metadata` 保存脱敏分组与费用来源，不保存委托原文。旧记录、人工费用及已确认费用保留原值，不自动修正历史估算；混合缺失与已返回费用、已同步成交事实或估算费用被手工修改时要求人工核对。每次同步前完整备份，任一成交冲突则整组回滚。所有估算仍应以结算后的实际费用核对。

## 统计月历

统计分析选择“本月”或“上月”时显示每日盈亏月历，按周一至周日排列，每天展示已实现盈亏和真实成交记录笔数，红色为盈利、绿色为亏损，无成交显示横线，未来日期不可选。点击日期展开当天统计，不改变月度筛选；股票/ETF 类型筛选同步生效。盈亏复用统计分析口径，做 T 在实际买回并关联后按买回日确认，不计入浮动盈亏。

## 交易计划

侧栏“交易计划”支持单独新建买入、卖出计划，卡片显示三位小数的计划价格、数量、未计费用的计划金额、选填日期和备注。可从已有标的填写或搜索其他股票/ETF，支持编辑、手动完成、取消、重新启用和删除，并按方向、状态筛选。买入数量为整百，卖出计划允许零股；这些为计划输入规则，不代表券商实际可交易数量。计划独立保存在 `trade_plans`，随数据库备份保存，不自动添加持仓、不生成成交、不提交委托、不因到价自动完成。日期仅用于排序和过期提示。更新与删除带版本号，防止多个窗口静默覆盖；示例模式不读取或修改真实计划。

## 做 T 测算

“做 T 委托”使用表格展示卖出价、数量、已买回与待买回数量、行情、期望价和净价差；点击“关联管理”展开买回委托明细及关联操作，保留整单设置和买回入口。

做 T 待买回列表、股票页及批次追踪中的待买回卡片按可靠委托归属合并，保留全部分笔成交 ID；待买回现价估算对整组剩余数量只估算一次买回佣金。做 T 页面“整单设置做 T”可一次标记或取消整笔卖出委托、设置期望买回价；已有关联须先解除才能取消。新增成交继承保存的整单设置。买回候选也按买入委托汇总，一次“整单关联并恢复”按成交时间分摊卖出、买回及原买入批次数量，支持部分数量、多批次和同买回委托追加关联；恢复及解除以整组关联为单位，事务内校验，操作前自动备份，冲突整组回滚。原有单笔接口保留；历史已关联数据不必重做，也不合并或删除实际交易。累计做 T 次数按卖出委托去重；缺少可靠委托证据的交易仍独立计数，不按同价同时间推断。

统计分析中的做 T 已实现盈亏在关联实际买回记录后确认，按对应卖出净收入减去实际买回支出计算，包含双边已记录费用。部分买回仅确认已买回数量，跨日买回归入买回成交日，待买回部分暂不计入。后续普通卖出的统计沿用原持仓成本，避免重复计算已确认的做 T 价差；实际账本成本和交易记录的已实现盈亏保持实际成交口径。统计页分别显示普通卖出盈亏与做 T 净价差。

股票页持仓均价、浮动盈亏和图表均价线采用同一结转统计成本，已实现盈亏与统计分析累计值一致；实际持仓均价另行保留供参考。做 T 待买回部分不计入已实现收益，实际成交记录及委托成本计算不受统计展示影响。

批次卡片显示原价盈亏，并对已关联买回的批次显示累计做 T 次数、扣双边费用后的累计净价差及“计入 T 后”金额。后者为剩余持仓按原买入成本的预计净盈亏加上归属本批次的历次已买回净价差；累计净价差保留历史数量，不按当前剩余数量缩减。同一卖出多次买回只计一次，多批次卖出按关联的原批次数量分摊，未买回部分不计入。

做 T 关系以 `t_buyback_allocations` 独立明细为准，逐条保存卖出 ID、实际买回 ID、原买入批次 ID、数量和是否恢复批次。复合外键随关联删除明细，原批次仍被引用时禁止直接删除；各关联总量、证券和先后顺序在写入时校验，恢复 JSON 为事务内生成的兼容缓存。第一次启动新版后台时，先在账本旁的 `backups/` 创建 `ledger-before-t-relations-*.sqlite3` 完整备份，再在事务内迁移，旧关联缺失的原批次分摊按原规则固定保存；保留未恢复状态，不自动搬移历史持仓。已有及新增关联的 FIFO 卖出固定批次匹配。启动时重建缓存，修改交易会重新验证关系，冲突回滚。CSV 导出新增“做T买回关系明细”，保留未恢复关联及完整原批次分摊；完整可恢复备份仍使用数据库备份。做 T 页面、统计分析和批次卡片共用按实际买回记录四舍五入到分的净价差，合并买回按卖出 ID 顺序分摊最后一分差额。

侧栏「做 T 测算」按先卖出、再买回同等数量的计划计算。选择持仓证券、关联批次，填写三位小数的卖出价与买回价，以及整百数量，即可查看价差收益、双边费用、净收益、卖出到手与买回支出。费用复用系统中股票/ETF 各自的佣金率、最低佣金和四舍五入规则；税费、过户费及滑点预算需手动补入每边的额外费用，默认 0 元表示未计入。每边按一笔成交测算。

保本买回价为按 0.001 精度可取得非负净收益的最高买回价，通过 Decimal 与二分查找计算，考虑最低佣金及佣金随成交额变化。价格变化表展示计划买回价上下的净收益变化；不提供价格走势预测。历史买入成本不参与本次价差收益计算，测算页选择批次用于参考数量；实际买回记录的恢复功能单独维护原批次归属与实际成本。

账本参考数量扣除已关联待确认卖出数量，股票排除当日及未来日期的买入批次。ETF 交易机制不依据代码猜测，实际可卖量通过「核对券商可卖」手动查询当前账户持仓；结果是查询时快照。超出参考数量时保留测算并明确提示，不把测算当成可交易确认。本页面不提交委托、不写入交易记录。`POST /api/analysis/t-trade` 仅读取费率并返回测算结果。

卖出窗口可以勾选「做 T · 卖出后待买回」，并选填三位小数的期望买回价。保存卖出记录后在「做 T 测算」上方的待买回列表查看；交易记录也显示做 T 标记。真实卖出需要关联买入批次，标记只作为本地元数据保存在委托意图中，不发送给券商；当日成交手动同步后继承标记，未成交委托不会形成待买回成交记录。

买回关联时默认按原卖出分摊顺序恢复批次，也可手动选择原批次及数量。恢复后继续使用原批次 ID、原买入价展示及原止盈止损设置；实际买回交易的日期、价格、金额和费用不修改。恢复数量的真实成本转入原批次，与原剩余持仓按成本加权，卡片同时显示最近买回价和实际每股成本。恢复批次的卡片预计盈亏、盈利率、到达成本判断、止盈止损和快捷达标卖出价统一按原买入价加原买入费用计算；这是原批次的参考口径。实际账本成本、已实现盈亏及卖出记录预览继续按真实买回成本核算，不将参考盈亏写入账本。未分配的买回数量继续保留为独立批次。

已有买回关联不会在升级时自动迁移，勾选显示已完成后可点击「恢复原批次」补做。恢复与解除都在事务内验证，不能超出原卖出分摊、实际买回数量或其他已恢复数量。为保护历史成本，原批次在买回后已有后续卖出时会阻止变更；买回批次的后续卖出占用或待确认委托不允许被恢复挤占。既有卖出匹配在恢复时固定，避免按原批次排序后静默改变历史匹配。已恢复买回交易与原批次均在账本中保留，原始成交价不覆盖。股票当日买回数量从做 T 测算的可卖参考数量中扣除。

买回仍按实际成交时间正常记录或同步。待买回列表可选择同证券、卖出之后的买入记录，关联全部或部分数量，支持跨日、多笔买回；同一买入数量不能重复关联。已完成默认隐藏，可勾选显示或解除关联。净价差按实际成交金额、费用及关联数量分摊，不额外写入利润记录。调整已关联交易时会验证方向、证券、时间与数量，避免破坏关联；删除买入记录会解除相应关联并恢复待买回数量。

股票详情页的「买入批次」也展示当前证券的待买回卡片，与买入批次一起按达标优先、交易时间倒序排列；显示按现价买回的预计净盈亏并支持点击买回。盈利达标页将待买回与持仓批次放在同一个卡片列表中，沿用距离目标金额、盈亏率和交易时间排序。待买回卡片按当前报价计算剩余卖出净额减买回金额及预计买回佣金的净价差，只计尚未买回部分；原卖出费用按剩余数量分摊，其他买回费用未计入。金额使用后端 Decimal 核算，报价变化后批量更新，刷新期间保留上次核算并标注。点击卡片打开买回窗口。待买回证券加入该页面现有的推送和轮询范围，已清仓证券同样覆盖。

待买回证券即使已清仓也会单独获取价格；交易时段内按自动刷新设置更新，时段外首次或手动获取一次。有效报价达到期望买回价时高亮显示，不自动下单。期望价可在原卖出记录中编辑。

## 行情

侧栏「行情桥接」展示连接状态、主客户端 PID 与构建适配、累计报价、各证券最后报价及年龄、最近回退快照来源和最近 30 条连接事件。页面每 2 秒读取状态，隐藏后停止读取；只续期持仓证券的本地观察，不额外请求网络行情。旧报价明确标记为过期，状态读取失败时保留上次内容并提示。报价计数和事件仅保存在当前后台内存，重启后清空。

本地桥接依赖 `frida==17.24.2`（Windows，已加入 requirements.txt）。当前观察点适配已分析的 32 位主客户端构建（PE 时间戳 `1787242618`、`1790057509`），由后台统一维护构建与观察位置配置。挂接前同时检查记录函数前缀、调用指令及 SDK 导出目标；更新同花顺后若构建未知或结构检查失败会自动回退。桥接只读取请求证券代码对应的最新价，不读取账户、委托或授权数据；不涉及 Level-2 权限。交易时段外停止观察及周期刷新，原有首次/手动获取一次报价的行为保留。可在启动后台前设置 `STOCK_ASSISTANT_NATIVE_QUOTES=0` 禁用桥接，`GET /api/market/bridge/status` 可查看连接状态、原因、进程号及有效报价数量。

最新价优先使用同花顺主客户端（`hexin.exe`）的本地桥接：后台通过 Frida 只读观察主界面已解码的最新价，多个页面共享一个观察会话，不另开 HTTP 监听端口。需要主客户端运行、登录，并已订阅相应证券的行情（例如自选或当前页面）；桥接本身不创建证券订阅。没有收到报价、客户端退出、版本不匹配或超过 12 秒未更新时，依次回退到腾讯、东方财富。五档盘口和昨收等元数据使用腾讯、东方财富公开快照，盘口的手数转换为股/份，页面分别显示价格和盘口的实际来源与时间。行情链路不调用 `xiadan.exe` / `xiadanctl.exe` 的快照、推送或日 K 接口；券商账户查询、成交同步和交易接口继续使用下单客户端。

近一年不复权日 K 使用腾讯行情，失败后回退到 AKShare 东财。分时曲线使用腾讯公开行情。日 K 来源单独显示，缓存不会混用报价与日线来源。开启自动刷新后优先使用桥接持续更新最新价；未被桥接覆盖的证券及五档等元数据使用公开行情补充，桥接可用时元数据每 15 秒补充，超过 15 秒的盘口不作为新盘口。买卖窗口打开及手动刷新时单独获取盘口。桥接无法提供推送时使用公开行情轮询，并在 30 秒后尝试重连桥接。设置中可关闭「优先实时推送」，改用 5 / 10 / 30 秒轮询。推送期间曲线仍每 30 秒更新。切换标的、离开持仓页或隐藏页面会关闭订阅。

免费公开数据源可能限流或不可用。获取失败不影响记账，已有快照会保留并提示过期。无行情时，仅用真实交易日期、成交价格与买入成本绘图，不生成模拟行情曲线替代真实行情。

行情请求在独立进程中执行，最多等待 22 秒；最新快照缓存 2 秒、分时曲线缓存 30 秒、日 K 缓存 10 分钟。自动刷新默认关闭，可在设置启用（默认每 5 秒，可选 10 / 30 秒，仅当前标的且页面可见时）。手动刷新也受缓存限制。近一年之前的买入仍可画成本线，但没有相应历史行情曲线。

图表使用 TradingView Lightweight Charts，保留图表上的 TradingView 归属链接。详见 [开源项目及许可](https://github.com/tradingview/lightweight-charts)。

## 数据与恢复

数据库路径：`data/ledger.sqlite3`，不会上传交易记录；查询行情时仅发送证券代码。不要把运行服务暴露到公网。

备份按钮使用 SQLite backup API 导出一致的完整快照。恢复时先停止服务，将现有 `data/ledger.sqlite3` 另存备份，再把下载的 `ledger-backup.sqlite3` 复制为 `data/ledger.sqlite3`，重启即可。CSV 目前只支持导出，不支持导入恢复。

### 持续行情推送接口

`GET /api/market/{code}/stream` 为已有标的提供 SSE，事件包括 `quote`（规范化价格和五档）、`heartbeat` 和 `state`。后端转发共享本地桥接的最新价，并通过腾讯、东方财富补充缺失证券及盘口。浏览器订阅共享一个原生观察会话，不再沿用旧 CLI 的两条订阅限制；公开行情补充任务仍限制为两个并发，并合并同证券的补充请求。桥接无报价或订阅停滞时返回 `fallback` 状态，浏览器恢复公开行情轮询并定时重连。客户端断开时取消该订阅的补充任务；推送更新同时供 REST 报价缓存使用。浏览器仅收到行情字段与连接状态，不返回原始授权错误或会话标识。

### 普通账户买卖委托

买入、卖出弹窗共用原来的交易表单，底部分为“保存记录”和“真实买入 / 真实卖出”两个操作。真实买卖使用当前标的、价格和数量直接预览，核对确认后才提交，返回修改保留表单内容。编辑历史记录与示例模式没有真实买卖入口。真实委托不使用账本批次、历史交易时间或手工费用。券商账户页也提供“买入委托”“卖出委托”，持仓行可直接打开卖出。输入六位代码、明确价格和数量，先预览可交易数量，再核对当前同花顺普通账户及全部委托参数，勾选确认并提交。原“记录买入/卖出”继续用于手工记账；委托受理不会自动记为成交或写入账本。

`POST /api/broker/trade/preview` 接收 code、side、price、quantity；`POST /api/broker/trade/submit` 只接收 preview 返回的一次性 ticket 与 confirmed:true。30秒预览到期需重做；提交前重新检查登录、账户类型和可交易数量。普通账户接口没有账户绑定预览标识，确认期间请勿切换账户或退出重登；发生切换应返回重新预览。信用交易暂未接入。

调用仅通过官方 xiadanctl.exe order-preview/order-submit，原生授权仍由同花顺处理。提交后查询当日委托及成交确认柜台状态。票据在调用前消费，超时或结果不明确不会自动重试；服务重启后旧票据失效。委托端点要求浏览器同源 Origin，原始账户标识不返回页面。开发测试使用模拟提交，未发送真实委托。

### 成交同步、券商仓位和自选同步

从买入批次打开真实卖出时，预览及确认页保留本地批次 ID；仅证券、方向、价格和数量发送给同花顺。
提交前先保存本地委托意图，返回明确委托号后建立持久关联，委托号仅保存摘要。
在“当日成交”同步卖出时，通过委托号精确关联 `buy_lot_id`，同一委托的分笔成交沿用该批次。
没有明确委托号的结果、旧委托或客户端外下单，不按价格和时间猜测；先手动选择买入批次，或明确选择先进先出，再同步。
手动指定批次后，如该成交包含委托号，同一委托的后续成交也会沿用选择；页面刷新后可显示自动关联。
批次缺失、数量不足、与已有记录的成本匹配冲突时拒绝同步；不自动修改原记录。
这套关联用于当日单笔成交同步。历史成交批量同步继续使用原有预览流程。
重启源码后端后自动建立关联表；不会自动提交委托或补写已有卖出记录。

持仓或盈利达标卡片有未结束的卖出标记时，页面每 5 秒通过 `POST /api/broker/trade/refresh-status` 只读查询当日委托。
仅按已关联的委托号更新成交、撤单、拒单及部分成交数量，不按价格或时间猜测；查询失败或查询中缺少该委托不会清除原状态。
确认成交后继续查询当日成交明细，按准确关联的委托号和成交编号逐笔自动同步到账本，沿用原买入批次。
自动同步复用防重复、完整备份和事务内持仓核算；成交费用缺失时按费率估算并在记录中注明。既有记录不覆盖。
已成交但明细尚未完整返回时继续轮询；信息不足、成本批次冲突或可卖数量不足时显示“同步待处理”，保留原账本并在后续查询中重试。
撤单和拒单只更新标记，不写卖出交易。全部结束且成交已同步后停止轮询，窗口隐藏时暂停、恢复可见后继续。
未关联委托号的成交不自动猜测匹配，需要先在当日成交中手动选择批次；本功能不自动导入其他无关委托。

券商账户顶部“成交同步”按选定日期查询历史成交，先预览待导入、已存在和冲突记录，确认后只新增成交。用实际成交金额和资金变动推算总费用；缺失费用、买入历史不足、类型未支持或已有记录事实冲突会阻止导入。同期相同成交逐笔匹配，持久记录已导入成交指纹，重复同步不会重复记账。导入前完整备份，事务内核算，预览后账本变化需重做预览。当天未结算的成交可能暂未进入历史查询；请稍后再同步。当前支持普通账户的股票与ETF，不覆盖已有交易、批次、备注或盈利目标。

共用交易表单的仓位数量默认取券商账户，点击全仓、1/2、1/3、1/4仓通过 order-preview 按明确价格获取当前可交易数量；买入及分仓向下取整到100，全仓卖出保留零股。卖出可切回本地账本，使用历史批次口径；编辑历史买入及示例模式直接填写数量。查询数量不会提交委托，真实买卖仍须预览并确认。

券商账户顶部“自选同步”读取同花顺自选，勾选股票/ETF后导入“我的标的”，跳过指数及其他品种，不覆盖已有名称或创建交易。可选择本地标的加入同花顺自选；收到 pending 不等于加入成功，后端刷新并读取确认。自选刷新是异步请求，如缓存尚未更新可再次读取。

新增端点：POST /api/broker/sync/preview、/apply；POST /api/broker/trade/size；GET /api/broker/watchlist；POST /api/broker/watchlist/refresh、/import、/add。所有写操作要求同源 Origin。成交同步预览5分钟有效；应用仅接受服务端预览票据，客户端不能替换成交参数。
### Windows 桌面便携版

运行 release/StockAssistant/StockAssistant.exe，保留同目录的 StockAssistantWorker.exe 与 _internal。主程序用 WebView2 显示现有React界面，辅助程序管理本地 FastAPI 后台及有界行情/搜索子进程。无须在使用电脑上安装 Python 或 Node.js；需要 Microsoft Edge WebView2 Runtime。关闭窗口后发送退出指令，正常停止服务；Windows Job Object 保护本次服务及其子进程，异常退出也会清理，不影响已运行的同花顺。

默认数据目录为 %LOCALAPPDATA%/StockAssistant，包含 ledger.sqlite3、logs 和 webview（界面偏好）。首次运行创建空账本；需要迁移时可自行在 portable.json 设置 first_run_import，通过 SQLite backup 复制指定账本，原文件保留，目标数据库存在时不覆盖。生成的配置不包含本机账本路径。发布目录与压缩包不包含个人数据库。希望数据随文件夹移动时，在 portable.json 设置 "data_directory": "data"；迁移或升级时保留该目录。port 默认8000，重复启动会提示已运行，端口被其他程序占用时提示，不会终止其他服务。

构建命令：powershell.exe -NoProfile -ExecutionPolicy Bypass -File build-portable.ps1。此命令安装 requirements-desktop.txt、构建前端、生成两个共享依赖的EXE和 release/StockAssistant-Windows-x64.zip，并验证随附官方 xiadanctl.exe 的哈希。已有便携目录 data/ledger.sqlite3 时拒绝覆盖构建。

桌面源码入口 desktop.py；路径和子进程入口由 backend/runtime.py 统一管理。源码启动仍用 python -m，冻结版本显式调用控制台辅助EXE，从而可靠捕获JSON输出，主窗口无控制台。数据库备份和CSV下载已允许，WebView2会显示保存文件对话框。
